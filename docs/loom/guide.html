Overview

loom is a component framework for a terminal. You write functions that return a description of what to show; the runtime decides which live instance each one is, hands it a rectangle, and routes events back to it.

You will learn

  • What a component is, and what it is not
  • Where state lives
  • How an event finds the component that cares
  • Where your existing painting code goes

The shape #

#[component]
fn StatusBar(scope: &mut Scope, file: Option<File>, line: u32) -> Node {
    rsx! {
        Row { height: Cells(1), ..,
            Text { text: name_of(file) }
            Gap  { width: Fill(1), .. }
            Text { text: format!("line {line}") }
        }
    }
}

That is the whole contract. No trait to implement, no lifecycle methods, no rectangle arithmetic.

Three directions #

DirectionCarriesHow
Downpropsthe parent writes them in rsx!
Down, skipping levelscontextprovide_context above, context::<T> below
Upmessagesmessage(value) in a listener, caught by an ancestor

A child never holds a reference to its parent. When the explorer wants a file opened, it sends a value upward and something above decides what that means.

Note

There is no virtual DOM diff of cells. ratatui already compares the previous and current buffers and writes only what changed. What reconciliation buys here is identity — knowing which live component a tree position is, and therefore whose state is whose.

Where painting goes #

A component is worth having when it needs identity: state that survives a frame, its own focus, its own events, its own slot in the layout. A line of syntax-highlighted text needs none of those, so it stays a function. 

Component tree      ← identity, focus, events, state   (~8 of these)
     │
   Canvas           ← the seam
     │
 render/ functions  ← pure painting, unchanged

Everything already in render/ — cells.rs, line.rs, gutter.rs, column.rs — keeps working untouched, called inside a Canvas.

Writing a component

One function, one file. Its state, its layout, its painting and its keys all live together.

The signature #

#[component]
fn Counter(scope: &mut Scope, start: u32) -> Node { /* … */ }

The first parameter is always scope: &mut Scope — your own slot, which hooks need. Every parameter after it becomes a field of the generated props struct, so the caller writes them as a struct literal and a typo is a compile error naming the field.

You writeThe macro generates
fn Counter(scope, start: u32)struct CounterProps { start: u32 }
Counter { start: 3 }Counter::build(CounterProps { start: 3 })
Note

Props are 'static — no borrowing from the frame. Share large values with Rc; that is one pointer increment per frame, and it buys memo comparison and listeners that outlive the render.

A whole one #

#[component]
fn Counter(scope: &mut Scope, start: u32) -> Node {
    let theme = context::<Theme>(scope);
    let count = use_state(scope, || start);

    let listeners = Listeners::new()
        .on_key(move |key| match key {
            key!(j) => { count.edit(|c| *c += 1); Bubble::Stop }
            key!(k) => { count.edit(|c| *c = c.saturating_sub(1)); Bubble::Stop }
            _       => Bubble::Continue,
        });

    rsx! {
        Row { height: Cells(1), fill: theme.normal, listeners, ..,
            Text { text: format!("count {}", count.cloned()) }
        }
    }
}

Hooks first, then the listeners, then the shape. That order is a habit, not a rule — but hooks must run unconditionally, so putting them at the top makes it obvious that they do.

Describing

rsx!

The shape of a frame, written as a tree you can read. Props are a struct literal, so the compiler checks them by name.

Props #

ExplorerPane { files: files.clone(), focused: true }

A misspelled prop is "struct ExplorerPaneProps has no field named focusd", pointing at your token. A missing one is "missing field files". No builder can beat that.

Defaults #

// no props written — every default
Row { Column { Text { text: "hello" } } }

// one prop written — `..` supplies the rest
Row { gap: 1, .., Column { /* … */ } }

Write no props and you get the defaults; write .. and you get the rest of them. Built-in hosts derive Default; your own components normally do not, so their props are all required.

Control flow #

Column {
    if let Some(buffer) = shown {
        DiffPane { buffer }
    } else {
        Text { text: "nothing open" }
    }

    for file in files.iter() {
        Row { key: file.path(), .., Text { text: file.name() } }
    }
}
Pitfall

Key every child of a list, or none of them. A key is what carries a child's state when the list is reordered. Half-keyed lists panic (P6.1), and duplicate keys panic (P6.2).

Layout

One axis per container, in whole terminal cells. No floats, no rounding, no flexbox.

Sizes #

SizeMeans
Cells(n)exactly n cells
Fill(w)a share of what is left, by weight
Percent(n)a share of the parent, rounded down
Autoas much as the content measures
Row {
    Column { width: Cells(40), min_width: Cells(8),  .., ExplorerPane { files } }
    Column { width: Fill(1),   min_width: Cells(20), .., DiffPane { buffer } }
}

When it does not fit #

Flexbox squashes. This does not: if any child would fall below its min, the container assigns nothing and paints its too_small node instead. 

Column {
    too_small: rsx! { Text { text: "terminal too small" } }, ..,
    /* … */
}
Note

This is the rule the current code writes by hand as a returned bool threaded through four functions. Here it is a property of the container.

Describing

Canvas

A leaf that says: give me a rectangle, I will paint it myself.

A diff pane shows forty lines of syntax-highlighted text over a hundred and twenty columns. Expressing each character as a node would be thousands of nodes to reconcile every frame, for nothing — none of them remember anything or respond to anything. 

Canvas {
    width: Fill(1), height: Fill(1), focusable: true, listeners, ..,
    paint: move |area: Rect, cells: &mut Cells| {
        // today's draw code, unchanged
        let Some(frame) = render::layout::columns(area, divider, orig, mods) else { return };
        for (side, column) in frame.columns() {
            render::column::draw(cells, column, side, &lines, painter);
        }
    },
}

where the rectangle iswhat goes in it
who has focus—
which component was clickedwhich line was clicked
what survives the frame—
Pitfall

Paint reads; it does not write. set or edit from inside a paint callback panics (P7.2). read, cloned and edit_without_redraw are legal.

Hooks

use_state

use_state gives a component a value that survives a redraw — a cursor row, a fold, a scroll position.

You will learn

  • How to add state to a component
  • Which of the five ways to write it you want
  • Why the handle works inside an event listener
  • When a write redraws and when it does not

Reference #

Call it at the top of your component, once per value.

let cursor = use_state(scope, || 0u32);

The closure runs once, when the component mounts. On every render after that it is ignored and you get the value that is already there.

Signature #

#[track_caller]
pub fn use_state<T: 'static>(
    scope: &mut Scope,
    first: impl FnOnce() -> T,
) -> State<T>;
ParameterMeans
scopeYour component's own slot. The first parameter every component takes.
firstBuilds the value the first time. Never called again.

It returns a State<T> — a handle, not the value. The handle is eight bytes naming a slot, so it is Copy: move it into as many listeners as you like without cloning anything.

Reading #

// Borrow briefly. The closure keeps the borrow short and typed.
let row = cursor.read(|c| *c);
let line = view.read(Viewport::cursor);

// Or take a copy, when that is all you want.
let row = cursor.cloned();

Prefer read for anything larger than a number. cloned copies, and copying a Vec every frame is a cost you did not mean to pay.

Writing #

Three ways, and they differ only in when they redraw.

CallWritesRedraws
set(v)replacesalways
set_if_changed(v)replacesonly if it differs
edit(f)in placealways
edit_without_redraw(f)in placenever
cursor.set(5);
cursor.edit(|c| *c += 1);

// Recomputed every render from props — only mark when it really moved.
divider.set_if_changed(width / 2);

edit_without_redraw is for a value the frame is already about to read — a viewport height the layout just settled, a syntax span that arrived for a line already on screen. Marking there would redraw the frame you are in the middle of preparing.

Pitfall

Call use_state unconditionally. Never inside an if, a loop, or after an early return. Slots are found by call order, so a skipped call shifts every hook after it. 

// ✗ the second render finds a Memo where it left a State
if split {
    let width = use_state(scope, || 40);
}

// ✓ always call it; branch on the value instead
let width = use_state(scope, || 40);
let shown = if split { width.cloned() } else { 0 };

The first render that diverges panics, naming both call sites (P4.1).

In a listener #

A listener runs long after your render returned, and it has no scope. The handle is what carries over. 

let cursor = use_state(scope, || 0u32);
let rows = buffer.read(Buffer::view_lines);

let listeners = Listeners::new()
    .on_key(move |key| match key {
        key!(j) => { cursor.edit(|c| *c = (*c + 1).min(rows - 1)); Bubble::Stop }
        key!(k) => { cursor.edit(|c| *c = c.saturating_sub(1)); Bubble::Stop }
        _       => Bubble::Continue,
    });

Both closures capture cursor by move, and both work — because the handle is Copy, not because anything was cloned.

Note

You cannot call a hook inside a listener, and the compiler says so: listeners are 'static closures, and &mut Scope is not. React's first rule, enforced by the type system instead of a lint.

Writing during render #

Legal, and how a component reacts to its own props — but a write marks the component, so a component that writes a different value every render never settles.

Pitfall

Sixteen renders of one component in one frame is a bug, not a slow frame. The runtime stops and says so: 

DiffPane ran 17 times in one frame — a component that
sets state on every render never settles

Reach for set_if_changed when the value is derived from props, and edit_without_redraw when the frame is already going to read it.

Under the hood

State<T> is two integers — the scope that owns it and the slot index inside that scope. 

pub struct State<T> {
    scope: ScopeId,
    slot:  u16,
    _value: PhantomData<T>,
}

The value itself lives in the slot the hook allocated. Nothing is duplicated and no arena is involved, which is how the handle stays Copy without the unsafe that other frameworks need for the same trick.

When the component unmounts, its slots drop and the scope's generation is bumped, so a handle that outlived its component fails a check (P4.3) rather than reading a stranger's value.
