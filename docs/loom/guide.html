Start

Overview

loom is a component framework for a terminal. You write functions that return a description of what to show; the runtime decides which live instance each one is, hands it a rectangle, and routes events back to it.

You will learn

  • What a component is, and what it is not
  • Where state lives
  • How an event finds the component that cares
  • Where your existing painting code goes

The shape #

#[component]
fn StatusBar(scope: &mut Scope, file: Option<File>, line: u32) -> Node {
    rsx! {
        Row { height: Cells(1), ..,
            Text { text: name_of(file) }
            Gap  { width: Fill(1), .. }
            Text { text: format!("line {line}") }
        }
    }
}

That is the whole contract. No trait to implement, no lifecycle methods, no rectangle arithmetic.

Three directions #

DirectionCarriesHow
Downpropsthe parent writes them in rsx!
Down, skipping levelscontextprovide_context above, context::<T> below
Upmessagesmessage(value) in a listener, caught by an ancestor

A child never holds a reference to its parent. When the explorer wants a file opened, it sends a value upward and something above decides what that means.

Note

There is no virtual DOM diff of cells. ratatui already compares the previous and current buffers and writes only what changed. What reconciliation buys here is identity — knowing which live component a tree position is, and therefore whose state is whose.

Where painting goes #

A component is worth having when it needs identity: state that survives a frame, its own focus, its own events, its own slot in the layout. A line of syntax-highlighted text needs none of those, so it stays a function. 

Component tree      ← identity, focus, events, state   (~8 of these)
     │
   Canvas           ← the seam
     │
 render/ functions  ← pure painting, unchanged

Everything already in render/ — cells.rs, line.rs, gutter.rs, column.rs — keeps working untouched, called inside a Canvas.

Writing a component

One function, one file. Its state, its layout, its painting and its keys all live together.

The signature #

#[component]
fn Counter(scope: &mut Scope, start: u32) -> Node { /* … */ }

The first parameter is always scope: &mut Scope — your own slot, which hooks need. Every parameter after it becomes a field of the generated props struct, so the caller writes them as a struct literal and a typo is a compile error naming the field.

You writeThe macro generates
fn Counter(scope, start: u32)struct CounterProps { start: u32 }
Counter { start: 3 }Counter::build(CounterProps { start: 3 })
Note

Props are 'static — no borrowing from the frame. Share large values with Rc; that is one pointer increment per frame, and it buys memo comparison and listeners that outlive the render.

A whole one #

#[component]
fn Counter(scope: &mut Scope, start: u32) -> Node {
    let theme = context::<Theme>(scope);
    let count = use_state(scope, || start);

    let listeners = Listeners::new()
        .on_key(move |key| match key {
            key!(j) => { count.edit(|c| *c += 1); Bubble::Stop }
            key!(k) => { count.edit(|c| *c = c.saturating_sub(1)); Bubble::Stop }
            _       => Bubble::Continue,
        });

    rsx! {
        Row { height: Cells(1), fill: theme.normal, listeners, ..,
            Text { text: format!("count {}", count.cloned()) }
        }
    }
}

Hooks first, then the listeners, then the shape. That order is a habit, not a rule — but hooks must run unconditionally, so putting them at the top makes it obvious that they do.

Describing

rsx!

The shape of a frame, written as a tree you can read. Props are a struct literal, so the compiler checks them by name.

Props #

ExplorerPane { files: files.clone(), focused: true }

A misspelled prop is "struct ExplorerPaneProps has no field named focusd", pointing at your token. A missing one is "missing field files". No builder can beat that.

Defaults #

// no props written — every default
Row { Column { Text { text: "hello" } } }

// one prop written — `..` supplies the rest
Row { gap: 1, .., Column { /* … */ } }

Write no props and you get the defaults; write .. and you get the rest of them. Built-in hosts derive Default; your own components normally do not, so their props are all required.

Control flow #

Column {
    if let Some(buffer) = shown {
        DiffPane { buffer }
    } else {
        Text { text: "nothing open" }
    }

    for file in files.iter() {
        Row { key: file.path(), .., Text { text: file.name() } }
    }
}
Pitfall

Key every child of a list, or none of them. A key is what carries a child's state when the list is reordered. Half-keyed lists panic (P6.1), and duplicate keys panic (P6.2).

One axis per container, in whole terminal cells. No floats, no rounding, no flexbox.

Sizes #

SizeMeans
Cells(n)exactly n cells
Fill(w)a share of what is left, by weight
Percent(n)a share of the parent, rounded down
Autoas much as the content measures

    Column { width: Cells(40), min_width: Cells(8),  .., ExplorerPane { files } }

When it does not fit #

Flexbox squashes. This does not: if any child would fall below its min, the container assigns nothing and paints its too_small node instead. 

Column {
    too_small: rsx! { Text { text: "terminal too small" } }, ..,
    /* … */
}
Note

This is the rule the current code writes by hand as a returned bool threaded through four functions. Here it is a property of the container.

Canvas

A leaf that says: give me a rectangle, I will paint it myself.

A diff pane shows forty lines of syntax-highlighted text over a hundred and twenty columns. Expressing each character as a node would be thousands of nodes to reconcile every frame, for nothing — none of them remember anything or respond to anything. 

Canvas {
    width: Fill(1), height: Fill(1), focusable: true, listeners, ..,
    paint: move |area: Rect, cells: &mut Cells| {
        // today's draw code, unchanged
        let Some(frame) = render::layout::columns(area, divider, orig, mods) else { return };
        for (side, column) in frame.columns() {
            render::column::draw(cells, column, side, &lines, painter);
        }
    },
}

Hooks

use_state

use_state gives a component a value that survives a redraw — a cursor row, a fold, a scroll position.

You will learn

  • How to add state to a component
  • Which of the five ways to write it you want
  • Why the handle works inside an event listener
  • When a write redraws and when it does not

Reference #

Call it at the top of your component, once per value.

let cursor = use_state(scope, || 0u32);

The closure runs once, when the component mounts. On every render after that it is ignored and you get the value that is already there.

Signature #

#[track_caller]
pub fn use_state<T: 'static>(
    scope: &mut Scope,
    first: impl FnOnce() -> T,
) -> State<T>;
ParameterMeans
scopeYour component's own slot. The first parameter every component takes.
firstBuilds the value the first time. Never called again.

It returns a State<T> — a handle, not the value. The handle is eight bytes naming a slot, so it is Copy: move it into as many listeners as you like without cloning anything.

Reading #

// Borrow briefly. The closure keeps the borrow short and typed.
let row = cursor.read(|c| *c);
let line = view.read(Viewport::cursor);

// Or take a copy, when that is all you want.
let row = cursor.cloned();

Prefer read for anything larger than a number. cloned copies, and copying a Vec every frame is a cost you did not mean to pay.

Writing #

Three ways, and they differ only in when they redraw.

CallWritesRedraws
set(v)replacesalways
set_if_changed(v)replacesonly if it differs
edit(f)in placealways
edit_without_redraw(f)in placenever
cursor.set(5);
cursor.edit(|c| *c += 1);

// Recomputed every render from props — only mark when it really moved.
divider.set_if_changed(width / 2);

edit_without_redraw is for a value the frame is already about to read — a viewport height the layout just settled, a syntax span that arrived for a line already on screen. Marking there would redraw the frame you are in the middle of preparing.

Pitfall

Call use_state unconditionally. Never inside an if, a loop, or after an early return. Slots are found by call order, so a skipped call shifts every hook after it. 

// ✗ the second render finds a Memo where it left a State
if split {
    let width = use_state(scope, || 40);
}

// ✓ always call it; branch on the value instead
let width = use_state(scope, || 40);
let shown = if split { width.cloned() } else { 0 };

The first render that diverges panics, naming both call sites (P4.1).

In a listener #

A listener runs long after your render returned, and it has no scope. The handle is what carries over. 

let cursor = use_state(scope, || 0u32);
let rows = buffer.read(Buffer::view_lines);

let listeners = Listeners::new()
    .on_key(move |key| match key {
        key!(j) => { cursor.edit(|c| *c = (*c + 1).min(rows - 1)); Bubble::Stop }
        key!(k) => { cursor.edit(|c| *c = c.saturating_sub(1)); Bubble::Stop }
        _       => Bubble::Continue,
    });

Both closures capture cursor by move, and both work — because the handle is Copy, not because anything was cloned.

Note

You cannot call a hook inside a listener, and the compiler says so: listeners are 'static closures, and &mut Scope is not. React's first rule, enforced by the type system instead of a lint.

Writing during render #

Legal, and how a component reacts to its own props — but a write marks the component, so a component that writes a different value every render never settles.

Pitfall

Sixteen renders of one component in one frame is a bug, not a slow frame. The runtime stops and says so: 

DiffPane ran 17 times in one frame — a component that
sets state on every render never settles

Reach for set_if_changed when the value is derived from props, and edit_without_redraw when the frame is already going to read it.

Under the hood

State<T> is two integers — the scope that owns it and the slot index inside that scope. 

pub struct State<T> {
    scope: ScopeId,
    slot:  u16,
    _value: PhantomData<T>,
}

The value itself lives in the slot the hook allocated. Nothing is duplicated and no arena is involved, which is how the handle stays Copy without the unsafe that other frameworks need for the same trick.

When the component unmounts, its slots drop and the scope's generation is bumped, so a handle that outlived its component fails a check (P4.3) rather than reading a stranger's value.

See also #

  • use_memo — when the value is derived from something else
  • use_size — for the rectangle you were given
  • Events — where listeners come from
  • Workers — for a value that arrives from a thread

use_effect

Work to do after the frame is painted — ask a worker for something, start a watcher, react to a prop that changed.

You will learn

  • When an effect runs, and when it does not
  • How cleanup works without a cleanup function
  • How to reach a worker from inside one

Reference #

use_effect(scope, file.clone(), move |file, effect| {
    // runs after paint, whenever `file` differs from last time
});
ParameterMeans
depsCompared with PartialEq against the last render. Equal means skip.
runGets the deps and an Effect, which is how you reach a worker.

Effects run after paint, in a terminal for the same reason React runs them after commit: draw the frame first, then go ask for more.

Cleanup is a value, not a callback #

React returns a function. Here you return a value, and dropping it is the cleanup — which composes, because a thing that must be stopped already stops itself when dropped. 

use_effect(scope, path.clone(), move |path, _| {
    Watcher::watch(path)      // returned, so it is kept
});                             // dropped when `path` changes → stops

Return () when there is nothing to keep. No Option<Box<dyn FnOnce()>> anywhere.

Asking a worker #

The Effect handle makes a reply address that belongs to your component. See Workers for what happens on the other end. 

let buffer = use_state(scope, || None);
let outbox = context::<Rc<Outbox>>(scope);

use_effect(scope, file.clone(), move |file, effect| {
    let reply = effect.completion(move |response| {
        buffer.set(Some(response.into_buffer()));
    });
    outbox.send(Request::Open { file: file.clone(), reply });
});
Pitfall

The deps decide everything. Pass a value that changes when you want the effect to re-run — and only then. A Vec rebuilt every render is never equal to the last one, so the effect runs every frame. 

// ✗ a fresh Vec every render — the effect never stops firing
use_effect(scope, files.to_vec(), /* … */);

// ✓ an Rc compares by contents, and the parent only rebuilds it on a change
use_effect(scope, files.clone(), /* … */);
Note

Run it once and never again by passing () as the deps — () is always equal to itself.

use_memo

A value recomputed only when its dependencies change. For work you would not want to repeat every frame. 

let spans = use_memo(scope, version, |v| highlight(&text, *v));

Returns an Rc<T> — the same one, until deps differ.

Note

Reach for this when the computation is expensive, not by habit. A comparison and an Rc are not free either, and most values in a terminal frame are cheap to rebuild.

use_size

The rectangle this component was given — available before it paints, so a pane can size its contents to itself in the same frame. 

let area = use_size(scope);
view.edit_without_redraw(|v| v.set_height(area.height.into(), rows));

Why this is not a frame behind #

Layout happens before paint, and a component whose size changed is run again before the frame is painted. So the height you read is the height you are about to be drawn at, not the one from last time. 

reconcile → lay out → (size changed? run again) → paint → effects

That loop is capped at four rounds. A component that changes its own size every round would otherwise never settle.

Pitfall

Write the height with edit_without_redraw. Marking here would ask for a redraw of the frame you are in the middle of preparing.

Context

Values an ancestor offers to everything below it — the theme, a worker outbox, the key resolver. Read at any depth without threading props.

You will learn

  • How to offer a value and how to read it
  • What happens when two ancestors offer the same type
  • Why memoised components do not go stale

Offering and reading #

// near the root, once
provide_context(scope, theme);

// five levels down, without anyone between knowing
let theme = context::<Theme>(scope);

Reading walks up the parent chain and stops at the first ancestor that offered that type. Missing means a panic naming the type (P10.1); try_context answers None instead.

Note

There is no <Provider> component. provide_context at the top of a render does the same job and adds no node to the tree.

Shadowing #

Context is keyed by type. A nearer ancestor shadows a further one — so two different values of the same type need two newtypes, not one. 

// ✗ both are Rc<str>; the inner one wins everywhere below it
provide_context(scope, title);
provide_context(scope, subtitle);

// ✓ two types, two contexts
provide_context(scope, Title(title));
provide_context(scope, Subtitle(subtitle));
Under the hood

Every read is recorded on the scope as (TypeId, version). When a provider offers a different value the version moves, and any memoised component that recorded that type re-renders even though its props did not change.

Twenty lines, and without them memoisation would be a correctness bug rather than an optimisation.

Writing your own hook #

A hook is any function that takes scope and calls other hooks. Nothing special marks it — the same rule applies, so call it unconditionally. 

/// Resolve a key against this pane's keymap.
fn use_keymap(scope: &mut Scope, kind: KeymapType) -> State<Resolver> {
    let keys = context::<State<Resolver>>(scope);
    use_effect(scope, kind, move |kind, _| keys.edit(|r| r.enter(*kind)));
    keys
}

This is React's custom-hook pattern with nothing added: useDebounce is useState plus useEffect, and so is this.

Reacting

Events

Keys go to whoever has focus and rise until something stops them. Mouse goes to the deepest rectangle under the pointer and does the same.

You will learn

  • How to listen, and how to say you handled it
  • Why keys and mouse are routed differently
  • How a drag stays with the thing it started on
  • How a child asks its parent for something

Listening #

let listeners = Listeners::new()
    .on_key(move |key| { /* … */ Bubble::Stop })
    .on_mouse(move |mouse| { /* … */ Bubble::Stop })
    .on_wheel(move |lines| { /* … */ Bubble::Stop })
    .on_focus(move |has| { /* … */ })
    .on_message(move |chosen: &Chosen| { /* … */ Bubble::Stop });

rsx! { Canvas { listeners, focusable: true, .. } }
ReturnMeans
Bubble::StopMine. Nothing above me sees it.
Bubble::ContinueNot mine. Offer it to my parent.

Two ways to route #

EventStarts atThen
keythe focused nodeup through its ancestors
mouse, wheelthe deepest node under the pointerup through its ancestors
messagethe focused nodeup through its ancestors

This is the layering the current code writes by hand — buffer, then pane, then tab, then view, innermost first. Here the tree is the layering.

Note

Mouse carries both at (where on screen) and local (where inside your rectangle). Use local — it is already relative to you.

Dragging #

A text selection must keep receiving mouse events even when the pointer leaves the column it started in. Capture the pointer: 

.on_mouse(move |mouse| {
    match mouse.kind {
        MouseEventKind::Down(MouseButton::Left) => {
            capture_pointer();
            anchor.set(Some(mouse.local));
        }
        MouseEventKind::Up(_) => release_pointer(),
        _ => {}
    }
    Bubble::Stop
})

While captured, every mouse event goes to that node regardless of where the pointer is. There is no capture phase — this is the only thing a capture phase would have been for.

Asking a parent #

When only an ancestor can do the thing, send a value upward. The child holds no reference to anything above it. 

// the explorer, in a listener
message(Chosen(file));

// the root, listening
.on_message(move |Chosen(file): &Chosen| {
    opened.set(Some(file.clone()));
    Bubble::Stop
})
Note

A message is an ordinary value of your own type. There is no bus and no registry — it rises through the same path a key does, and any ancestor may take it.

Reacting

Workers

Ask a thread for something and have the answer arrive at the component that asked — not at a global inbox that has to work out who wanted it.

You will learn

  • Which of the two reply addresses you want
  • What a generation prevents
  • How this replaces one pending slot on Session

Two addresses #

TypeRepliesFor
Completion<T>one, then spenta file diff
Subscription<T>many, until closedsyntax spans, arriving in pieces

Both are made inside an effect, because that is where the request goes out.

use_effect(scope, file.clone(), move |file, effect| {
    let reply = effect.completion(move |response| {
        buffer.set(Some(response.into_buffer()));
    });
    outbox.send(Request::Open { file: file.clone(), reply });
});

The closure runs when the worker answers, with your component entered — so it may set state and ask for a redraw. It may not call a hook; it holds no scope.

What a generation prevents #

You open a.rs. Before it finishes you open b.rs. Then a.rs's reply lands. 

open a.rs   → effect runs, address generation 1
open b.rs   → deps changed, effect runs again, generation 2
a.rs replies → address says 1, the slot says 2 → refused
b.rs replies → 2 == 2 → delivered

The address carries the scope, the effect's slot, and the generation. A reply that arrives after the deps changed, or after the component unmounted, is refused rather than applied to whatever is there now.

Note

Today this case is handled by Session comparing the response's file against the one it is still waiting for. That check disappears: the address either matches or it does not.

What the loop does #

Components post requests to an outbox; the loop drains it after the frame, sends to the real workers, and delivers answers back to the addresses that came with them. 

Event::FileReady(response) => {
    pending.file.take().is_some_and(|reply| reply.complete(response))
}

One line, and it does not know what a diff is or which pane wanted one.

A list pane

The explorer, whole. It owns its list, its folds and its cursor; it paints with the code that paints it today; and when a file is chosen it says so upward. 

#[component]
fn ExplorerPane(scope: &mut Scope, files: Rc<[File]>) -> Node {
    let theme  = context::<Theme>(scope);
    let buffer = use_state(scope, || Buffer::explorer(files.to_vec()));
    let view   = use_state(scope, Viewport::new);
    let focus  = use_focus(scope);
    let area   = use_size(scope);

    // The watcher gave a new list. Rebuild it, and keep the reader on the
    // file they were looking at.
    use_effect(scope, files.clone(), move |files, _| {
        let landing = buffer.edit(|b| b.refresh(files.to_vec()));
        view.edit(|v| v.place(landing, buffer.read(Buffer::view_lines)));
    });

    let rows = buffer.read(Buffer::view_lines);
    view.edit_without_redraw(|v| v.set_height(area.height.into(), rows));

    let listeners = Listeners::new()
        .on_key(move |key| match key {
            key!(j) => { step(view, rows,  1); Bubble::Stop }
            key!(k) => { step(view, rows, -1); Bubble::Stop }
            key!(enter) => {
                if let Some(file) = file_at(buffer, view) { message(Chosen(file)) }
                Bubble::Stop
            }
            _ => Bubble::Continue,
        })
        .on_mouse(move |mouse| {
            let line = view.read(Viewport::top) + u32::from(mouse.local.y);
            if line < rows {
                view.edit(|v| v.place(line, rows));
                if let Some(file) = file_at(buffer, view) { message(Chosen(file)) }
            }
            Bubble::Stop
        })
        .on_wheel(move |lines| { view.edit(|v| v.scroll(lines, rows)); Bubble::Stop });

    rsx! {
        Canvas {
            width: Fill(1), height: Fill(1), focusable: true, listeners, ..,
            paint: move |area, cells| {
                draw_explorer(cells, area, &buffer.read(|b| b), &view.read(|v| v), theme)
            },
        }
    }
}

Nothing above this reaches into it. When it wants a file opened it sends Chosen upward and something above decides what that means.

A diff pane

Two columns of code, painted by the code that already paints them. Nothing in render/ changes. 

#[component]
fn DiffPane(scope: &mut Scope, file: File) -> Node {
    let theme  = context::<Theme>(scope);
    let outbox = context::<Rc<Outbox>>(scope);
    let buffer = use_state(scope, || None::<Rc<Buffer>>);
    let view   = use_state(scope, Viewport::new);
    let area   = use_size(scope);

    // Ask for the diff whenever the file changes. A reply for a file we have
    // since navigated away from is refused by its generation.
    use_effect(scope, file.clone(), move |file, effect| {
        let reply = effect.completion(move |response| {
            buffer.set(Some(Rc::new(Buffer::diff(response))));
        });
        outbox.send(Request::Open { file: file.clone(), reply });
    });

    let Some(buffer) = buffer.cloned() else {
        return rsx! { Text { text: "loading…", style: theme.normal } };
    };

    view.edit_without_redraw(|v| v.set_height(area.height.into(), buffer.view_lines()));

    rsx! {
        Canvas {
            width: Fill(1), height: Fill(1),
            min_width: Cells(20), focusable: true, ..,
            paint: move |area, cells| {
                // today's draw/buffer/side_by_side.rs, unchanged
                draw_side_by_side(cells, area, &buffer, &view.read(|v| v), theme);
            },
        }
    }
}
Note

The early return before the buffer arrives is legal because the hooks above it all ran. Returning before a hook is what breaks (P4.2).

The root

What holds the panes together — and what is left of Session afterwards. 

#[component]
fn Screen(scope: &mut Scope, files: Rc<[File]>, theme: Theme) -> Node {
    provide_context(scope, theme);
    provide_context(scope, use_state(scope, Outbox::default));

    let opened = use_state(scope, || None::<File>);
    let left   = use_state(scope, || 40u16);

    let listeners = Listeners::new()
        .on_message(move |Chosen(file): &Chosen| {
            opened.set(Some(file.clone()));
            Bubble::Stop
        })
        .on_key(move |key| match key {
            key!('>') => { left.edit(|w| *w = (*w + 4).min(100)); Bubble::Stop }
            key!('<') => { left.edit(|w| *w = w.saturating_sub(4).max(12)); Bubble::Stop }
            _ => Bubble::Continue,
        });

    let shown = opened.cloned();

    rsx! {
        Column {
            height: Fill(1), listeners,
            too_small: rsx! { Text { text: "terminal too small" } }, ..,

            Row { height: Fill(1), ..,
                Column {
                    width: if shown.is_some() { Cells(left.cloned()) } else { Fill(1) },
                    min_width: Cells(8), border: true, ..,
                    ExplorerPane { files: files.clone() }
                }
                if let Some(file) = shown {
                    Column { width: Fill(1), min_width: Cells(20), border: true, ..,
                        DiffPane { file }
                    }
                }
            }

            StatusBar { file: shown }
        }
    }
}
